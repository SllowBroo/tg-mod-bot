Telegram-бот для групповых чатов с рекламной рассылкой, приветствиями, быстрыми ответами и полноценной модерацией. Проект создан с фокусом на безопасное хранение настроек, предсказуемое поведение и устойчивую работу 24/7.

## Что умеет бот

| Модуль | Возможности |
| --- | --- |
| Реклама | Текст, фото, HTML-подпись, ссылки, ручная и интервальная отправка |
| Приветствия | Только новые участники, HTML и шаблоны имени/упоминания |
| Быстрые ответы | Настраиваемые ответы `купить дзо` и `купить мс` |
| Модерация | Бан, разбан, мут, размут, предупреждения и автобан после 3 нарушений |
| Безопасность | Команды только с `!`, проверка прав, rate limit, маскирование секретов |
| Надёжность | Автоперезапуск polling, SQLite WAL и защита от дублей планировщика |

Готовый бот на Python 3.11+, aiogram 3.x, SQLite и APScheduler. Он поддерживает рекламную рассылку, приветствия, быстрые ответы и модерацию. Все пользовательские команды начинаются с `!`; на обычные сообщения бот не отвечает.

## Архитектура

```text
telegram-group-bot/
├── app/
│   ├── handlers/
│   │   ├── ads.py          # реклама и приём фотографии
│   │   ├── welcome.py      # приветствие новых участников
│   │   ├── replies.py      # быстрые ответы
│   │   ├── moderation.py   # бан, мут, предупреждения, ID
│   │   └── errors.py       # неизвестные команды и ошибки
│   ├── bot.py              # Dispatcher, polling, автоперезапуск
│   ├── config.py           # .env без вывода секретов
│   ├── database.py         # SQLite, схема и запросы
│   ├── filters.py          # фильтры команд с !
│   ├── middlewares.py      # rate limit и учёт username
│   ├── scheduler.py        # единственный APScheduler
│   └── utils.py            # права, цели, интервалы, HTML
├── data/                   # локальная постоянная база (не коммитить)
├── main.py                 # запуск на Windows/обычном сервере
├── run_bothost.py          # отдельный запуск на Bothost
├── Dockerfile              # воспроизводимый Python 3.11
├── requirements.txt
├── .env.example
└── .gitignore
```

При запуске бот создаёт таблицы автоматически. В SQLite сохраняются разрешённая группа, рекламный контент и интервал, состояние рассылки, приветствие, быстрые ответы, известные пользователи и предупреждения. APScheduler хранит задания в памяти, но при каждом старте восстанавливает их из SQLite. Повторный вызов запуска планировщика блокируется, а рекламное задание создаётся с постоянным ID и `replace_existing=True`.

## 1. Создание бота и настройка группы

1. Откройте `@BotFather`, выполните `/newbot` и сохраните новый токен только у себя.
2. В `@BotFather` откройте `/mybots` → нужный бот → **Bot Settings** → **Group Privacy** → **Turn off**. Это важно для команд с `!` и запоминания username.
3. Добавьте бота в нужную группу.
4. Назначьте его администратором. Минимально включите:
   - отправку сообщений и фотографий;
   - добавление предпросмотра ссылок;
   - блокировку/ограничение пользователей (**Ban users / Restrict members**).
5. Администратор группы выполняет первую команду, например `!идентификатор`. Если `ALLOWED_CHAT_ID` не задан, эта первая админ-команда привяжет базу к текущей группе. После привязки бот отвергает команды из других групп.

Для жёсткой предварительной привязки задайте отрицательный ID супергруппы в `ALLOWED_CHAT_ID`. Если ID неизвестен, оставьте поле пустым, привяжите группу первой командой, затем выполните `!идентификатор`.

## 2. Запуск на Windows

Откройте PowerShell в корне проекта:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
```

Откройте `.env` и замените только шаблонное значение:

```dotenv
BOT_TOKEN=ВСТАВИТЬ_НОВЫЙ_ТОКЕН_ЗДЕСЬ
```

Не публикуйте `.env`, не присылайте его в чат и не добавляйте в Git. Запуск:

```powershell
python main.py
```

База появится в `data/bot.db`. Для остановки нажмите `Ctrl+C`. После неожиданного сбоя polling автоматически перезапускается с задержкой до 60 секунд.

### Автозапуск Windows через Планировщик заданий

Создайте задачу «При запуске компьютера», включите «Выполнять независимо от регистрации пользователя» и укажите:

- программа: полный путь к `.venv\Scripts\python.exe`;
- аргументы: `main.py`;
- рабочая папка: полный путь к корню проекта;
- в параметрах восстановления: перезапускать задачу при сбое.

Встроенный цикл перезапуска уже обрабатывает падение приложения; Планировщик заданий страхует завершение самого процесса или перезагрузку Windows.

## 3. Развёртывание на Bothost.ru

Актуальная документация Bothost указывает, что Python-зависимости автоматически устанавливаются из корневого `requirements.txt`, точку входа можно задать вручную, а постоянную SQLite-базу следует хранить в `/app/data`:

- [установка Python-зависимостей](https://bothost.ru/docs/installing-libraries);
- [главный файл / entrypoint](https://bothost.ru/docs/main-file-entrypoint);
- [переменные окружения](https://bothost.ru/docs/environment-variables);
- [постоянное хранение SQLite](https://bothost.ru/docs/database-storage).

Порядок деплоя:

1. Создайте Git-репозиторий и загрузите содержимое проекта. Файла `.env` в репозитории быть не должно.
2. В Bothost создайте Telegram-бота из этого репозитория и нужной ветки.
3. В дополнительных настройках укажите главный файл `run_bothost.py`.
4. В переменных окружения панели задайте:

   ```dotenv
   BOT_TOKEN=ваш_новый_токен
   DATABASE_PATH=/app/data/bot.db
   LOG_LEVEL=INFO
   COMMAND_COOLDOWN=1.0
   ALLOWED_CHAT_ID=-1001234567890
   ```

   `ALLOWED_CHAT_ID` можно временно не задавать и привязать группу первой админ-командой. Токен задавайте только как `BOT_TOKEN`.
5. Вариант без собственного Dockerfile: не включайте пользовательский Dockerfile — Bothost обнаружит Python и поставит `requirements.txt` автоматически.
6. Вариант с фиксированным Python 3.11: включите использование `Dockerfile` из репозитория. Его команда запуска уже указывает на `run_bothost.py`, а база — на `/app/data/bot.db`.
7. Выполните новый деплой. В runtime-логах должны появиться сообщения о запуске бота и планировщика; токен в них не выводится и дополнительно маскируется лог-форматтером.

Bothost перезапускает контейнер на уровне платформы, а `run_bothost.py` дополнительно перезапускает polling после временного сбоя Telegram API. Обновление кода не затрагивает `/app/data/bot.db`.

## 4. Команды

### Реклама — только администраторы

```text
!реклама текст <текст>
!реклама фото
!реклама интервал 5м
!реклама интервал 10м
!реклама интервал 1ч
!реклама интервал 2ч
!реклама старт
!реклама стоп
!реклама отправить
```

После `!реклама фото` отправьте фотографию обычным сообщением; подпись прикрепите к фото. `!отмена` прекращает ожидание. Если сохранены и фотография, и текст, фотография отправляется с подписью фото, а при отсутствии подписи — с рекламным текстом.

### Приветствие — только администраторы

```text
!приветствие <текст>
!приветствие вкл
!приветствие выкл
```

Шаблоны: `{name}`, `{username}`, `{mention}`, `{id}`. Пример:

```text
!приветствие <b>Добро пожаловать, {mention}!</b> Прочитайте <a href="https://example.com/rules">правила</a>.
```

Приветствие отправляется только участникам из события `new_chat_members`, не на обычные сообщения.

### Быстрые ответы

Настройка доступна администраторам:

```text
!текст купить дзо <текст>
!текст купить мс <текст>
```

Вызов доступен участникам:

```text
!купить дзо
!купить мс
```

Фразы `купить дзо` и `купить мс` без `!` игнорируются.

### Модерация — только администраторы

Команды можно отправлять ответом на сообщение пользователя либо с `@username`/числовым ID:

```text
!бан @username
!разбан @username
!мут 10м @username
!размут @username
!предупреждение @username
!снятьпредупреждение @username
!админы
!идентификатор
```

Для ответа на сообщение username указывать не нужно. Мут принимает `м`, `ч`, `д`, например `30м`, `2ч`, `7д` (от 30 секунд до 365 дней). После третьего предупреждения пользователь блокируется автоматически.

Telegram Bot API не позволяет боту найти произвольного пользователя только по username. Поэтому вариант с `@username` работает после того, как бот увидел хотя бы одно сообщение этого пользователя или событие его вступления. Ответ на сообщение — самый надёжный способ.

## 5. HTML и ссылки

Контент рекламы, подписи, приветствия и быстрых ответов отправляется с `parse_mode=HTML`. Используйте поддерживаемые Telegram теги, например `<b>`, `<i>`, `<u>`, `<s>`, `<code>` и `<a href="https://...">`. Некорректный HTML Telegram отклонит; при ручной отправке бот покажет понятную ошибку, не записывая сам текст или ссылки в лог.

Ограничения Telegram по длине также действуют: текст сообщения — до 4096 символов, подпись фотографии — до 1024 символов.

## 6. Проверка после запуска

Выполняйте тесты в разрешённой группе с двух аккаунтов: администратор и обычный участник.

1. `!идентификатор` — показывает ID и одновременно проверяет админ-доступ/привязку группы.
2. От обычного участника: `!админы` — бот должен отказать; обычное сообщение без `!` — бот молчит.
3. `!текст купить дзо <b>Тест ДЗО</b>` → от участника `!купить дзо`.
4. `!текст купить мс <a href="https://example.com">Тест МС</a>` → `!купить мс`.
5. `!приветствие <b>Привет, {mention}!</b>` → `!приветствие вкл` → добавить тестового участника.
6. `!реклама текст <b>Тестовая реклама</b> https://example.com` → `!реклама отправить`.
7. `!реклама фото` → отправить фото с подписью → `!реклама отправить`.
8. `!реклама интервал 5м` → `!реклама старт`; дождаться сообщения; затем `!реклама стоп` и убедиться, что новых отправок нет.
9. Ответом на сообщение тестового участника: `!мут 1м` → `!размут`.
10. Ответом: дважды `!предупреждение`, затем `!снятьпредупреждение`; отдельно на тестовом аккаунте проверить три предупреждения и автобан, после чего `!разбан <ID>`.
11. Перезапустить процесс и проверить, что настройки сохранились, а включённая реклама восстановилась ровно одним заданием.

## 7. Надёжность и безопасность

- Токен читается только из `BOT_TOKEN`; шаблонное или пустое значение завершает запуск до подключения.
- `.env` и SQLite исключены из Git.
- Токен не печатается в коде, ответах, README или штатных логах; похожие на токен строки маскируются.
- Ошибки Telegram API обрабатываются без аварийного завершения обработчика.
- Перед модерацией проверяются права администратора пользователя, статус цели и право бота ограничивать участников.
- Команды ограничены по частоте отдельно для пары «группа + пользователь».
- APScheduler запускается один раз; задания имеют стабильные ID и не дублируются.
- SQLite использует WAL и `busy_timeout`; настройки переживают рестарт.
- При падении polling процесс автоматически запускается снова с экспоненциальной задержкой.

Перед обновлением делайте резервную копию `data/bot.db` локально или `/app/data/bot.db` на Bothost.
